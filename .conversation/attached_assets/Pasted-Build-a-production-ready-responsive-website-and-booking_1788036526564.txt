## 2. Brand direction

Memento creates photo experiences that turn fleeting moments into memories people can hold, share and keep.

Core thought:

“The moment happens. The photo captures it. The print becomes the memento.”

Primary brand line:

MEMENTO  
Printed. Shared. Remembered.

Broader thought:

Because our memories go beyond the camera roll.

Desired feeling:

- Timeless
- Nostalgic
- Editorial
- Tactile
- Quietly luxurious
- Warm and emotionally meaningful
- Contemporary rather than vintage-themed

Conceptual references:

- Old photographs
- Beautiful paper
- Archival objects
- Art-exhibition posters
- Thoughtful Japanese packaging
- Restrained heritage typography
- Candid, genuine photography

Avoid:

- Generic photo-booth branding
- Bright event-company colors
- Blue
- Large black backgrounds
- Overly feminine pink styling
- Wedding-only aesthetics
- Playful Canva-style graphics
- Glassmorphism
- SaaS-dashboard styling on public pages
- Excessive gradients
- Camera, aperture or lens icons
- Confetti graphics
- Stock photos that look staged
- Excessive botanical decoration

Use botanical line art sparingly as a quiet editorial detail, not as a wellness or skincare motif.

## 3. Brand system

Extract the final values from Figma variables whenever possible.

Known fallback colors, only if Figma variables cannot be read:

- Faded Rose: `#CFA6A0`
- Warm Ivory/Paper: `#F4EFE7`
- Warm Ink: approximately `#241F1D`
- Muted olive, sage and taupe: retrieve from Figma; do not guess them

Usage:

- Warm ivory is the primary website canvas.
- Warm ink is the primary body-text color.
- Faded rose is the recognizable Memento accent and may carry selected large sections.
- Olive, sage and taupe are supporting accents used sparingly.
- Do not use blue.
- Do not make the entire website pink.
- Verify readable contrast, especially for body copy.

Typography:

- Instrument Serif Regular: large editorial display typography
- Instrument Serif Italic: brand lines, quotations and selected emphasis
- Manrope: navigation, body copy, forms, buttons and interface text
- Caveat: handwritten dates, moment numbers and short annotations only

Never use Caveat for body copy, navigation or major headlines.

Load the exact approved fonts. Do not silently substitute generic fonts. Prefer reproducible self-hosted web fonts or suitable font packages.

Visual language:

- Generous negative space
- Oversized editorial words
- Fine horizontal rules
- Small supporting labels
- Warm paper-like surfaces
- Restrained line-art botanicals
- Subtle paper grain when it does not harm performance
- Square and rectangular editorial layouts
- Minimal border radius
- No generic floating card grid

Motion:

- Restrained fades, crop reveals and gentle staggered transitions
- No bouncy animations
- No excessive parallax
- Support `prefers-reduced-motion`
- Keep animations lightweight and optional

## 5. Booking system scope

This is a professional booking-request workflow, not instant automatic confirmation.

Customers submit a request. Memento reviews availability and confirms personally.

Do not build customer accounts or online payments in version one.

### Public booking flow

Use a clear multi-step flow:

1. Event
2. Date and location
3. Experience preferences
4. Contact details
5. Review and submit

Collect:

- Full name
- Phone/WhatsApp number
- Email, if available
- Preferred contact method
- Event type
- Event date
- Start time
- End time or expected duration
- Venue
- City/location
- Estimated guest count
- Preferred print format
- Backdrop preference
- Selected add-ons
- Corporate or branded-experience requirements
- Additional notes
- Privacy/communication consent

Requirements:

- Prevent dates in the past.
- Validate all required fields on the client and server.
- Save incomplete form progress locally.
- Provide a complete review screen before submission.
- Generate a human-readable reference number.
- Store the request before sending notifications.
- Show a polished confirmation screen.
- Clearly state that submission does not guarantee confirmation.
- Provide a WhatsApp follow-up action after submission.

### Availability

Build basic availability management:

- Confirmed bookings and administrator-blocked dates should appear unavailable.
- Pending requests may be allowed for the same date but must be flagged as potential conflicts.
- Date and time overlap checks must run on the server.
- Do not expose private booking information publicly.
- Make the booking opening date configurable.
- Default booking opening date: `2026-10-01`.
- Before that date, support an “early booking request” or “notify me” mode without requiring a rebuild.

### Admin area

Protect `/admin` using Replit Auth or another secure platform-supported authentication method.

Allow an authorized administrator to:

- View booking requests
- Search and filter requests
- Open booking details
- Change status: pending, contacted, confirmed, declined or cancelled
- Add private internal notes
- Mark dates or time ranges unavailable
- See potential booking conflicts
- View a basic calendar
- Export bookings to CSV
- Open a prefilled WhatsApp conversation with the customer

Use an allowlisted administrator email stored in Secrets. Never hardcode credentials.

### Notifications

Create a provider-based notification system.

When configured:

- Notify Memento of a new booking request.
- Send the customer a booking-request acknowledgement.
- Include the booking reference number.
- Never describe the booking as confirmed until the administrator confirms it.

Use environment variables for email or WhatsApp providers. If credentials are unavailable, the booking must still save successfully and the admin dashboard must still work.

Do not expose API keys in frontend code.

## 6. Technical implementation

Use the project’s existing stack if one is already configured. Do not replace a functioning stack without a clear reason.

If beginning from an empty project, use:

- React with TypeScript
- A maintainable server/API layer
- Replit’s supported PostgreSQL database
- A typed ORM and committed migrations
- Server-side validation
- Replit Secrets for all credentials
- A non-static deployment because the site includes database and server functionality

Suggested database entities:

- `booking_requests`
- `blocked_availability`
- `admin_notes`
- `gallery_items`
- `site_settings`

Keep content, contact information and brand configuration centralized rather than scattered throughout components.

Create:

- `.env.example`
- Database migrations
- Seed data containing only clearly labelled sample records
- Setup and deployment README
- Admin handover instructions
- A central brand-token file
- A central site-content configuration

Never put real secrets in source control.
